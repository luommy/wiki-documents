# Product Wiring

本篇讲整机对外接口怎么接：供电怎么选、报警与扩展接口接什么、调试口在哪进。接口的完整规格清单见[产品总览](../0-overview.md)，各接口的 Web 配置见[外设 IO](./3-peripherals.md)。

## 1. 供电：PoE 还是 DC

NE503 支持两种供电，按现场基础设施选择：

| 方式 | 规格 | 适用 |
|:-----|:-----|:-----|
| **PoE** | 802.3at（RJ45 网口） | 现场有 PoE 交换机——一根网线同时供电与传数据，布线最简 |
| **DC 电源** | DC 12V（功耗约 5–6 W） | 无 PoE 基础设施，或集中供电 / 配 UPS 的场景 |

**怎么选**：

- 现场已有 PoE 交换机、且单端口功率档位满足 802.3at → 选 PoE，省一根电源线，安装最快；
- 现场只有普通交换机、或有集中 DC 供电 / UPS 保障 → 选 DC 12V，注意适配器的额定电流按 6 W 功耗留余量。

**注意**：

- 两种供电**不要同时接入**；
- 设备功耗按 6 W 做预算（含满载与外设）。

> DC 接头的极性定义与接插件规格以随设备提供的硬件资料为准。

## 2. 报警输入

整机对外引出 **1 路**报警输入（端子标识 Alarm IN），用于接门磁、红外对射、烟感等开关量信号。

**接线前先知道两件事**：

1. **当前固件版本报警输入的信号上报（事件总线 / API）尚未开放**——触发了报警输入，设备侧不会产生事件，Web 上也无从查看。需要报警联动的，由外部系统（如门禁控制器）直接读取传感器信号实现。
2. **报警联动方向是「输出」不是「输入」**——NE503 的联动能力是通过 **Wiegand ×2**（继电器 + 电平）向门禁等外部设备**输出**信号；平台侧由应用订阅 AI 事件后驱动（见[外设 IO · 联动说明](./3-peripherals.md)）。

**接线步骤**（场景：门磁 → Alarm IN）：

1. 断电，打开接线端子护盖，找到 **Alarm IN** 端子；
2. 按门磁的常开 / 常闭输出接至报警输入端子（具体针脚定义、公共端与输入类型见随设备硬件资料）；
3. 上电后验证：由于当前固件无事件上报，**Web 页面上看不到触发状态属于预期**，不是接线错误。

> 端子线序、输入电平类型（干接点 / 有源电平）与允许的输入范围以随设备提供的硬件资料为准，接线前务必核对。

## 3. RS-485 扩展接口

整机提供 **RS-485** 扩展接口，用于接云台（PTZ）或 RS-485 传感器（温湿度、雷达等）。

**先理解它的定位：透传字节通道**。设备不会替你「说」云台协议——RS-485 在软件侧只是一条可收发原始字节的通道：

- 应用通过 SDK / gRPC 调用 `Rs485Init` 设定波特率与串口参数，再用 `Rs485Tx` 发送、订阅 `EV_RS485_RX` 接收；
- 云台协议（如 Pelco-D/P、自定义协议）由你的应用自行编码实现；
- 端子 A/B 极性与线序见随设备硬件资料。

**接云台的典型步骤**（场景：RS-485 云台）：

1. 断电接线：云台的 A/B 线对应接至设备 RS-485 端子（A→A、B→B，极性反了通不了信），云台按自身规格供电；
2. 查云台协议手册，确认波特率、协议类型与云台地址（拨码）；
3. 设备上电，在应用里 `Rs485Init` 设成与云台一致的波特率，按协议格式发送控制帧，确认云台动作。

**接传感器的典型步骤**（场景：RS-485 温湿度传感器）：

1. 按传感器手册接 A/B 与供电（多数 RS-485 传感器还需共地）；
2. 应用里 `Rs485Init` 设成传感器波特率，按其协议（多为 Modbus RTU）轮询读取寄存器；
3. 收到合法响应帧即链路正常；无响应时按 [Troubleshooting §7.4](../5-troubleshooting.md#74-报警输入--wiegand--rs-485-运行时问题) 排查。

> RS-485 总线的终端电阻、偏置与多设备拓扑要求，以及端子是否引出 GND，以随设备提供的硬件资料为准。

## 4. 音频接口

**Line-In / Line-Out**：接现场拾音器与功放扬声器，实现监听与对讲；Web 侧在 **Peripherals → Mic Input / Speaker Output** 启用。

## 5. 调试接口

设备上有**三类串口，用途和对象都不同**，接错轻则不通、重则损坏接口：

| 类型 | 用途 | 谁用 |
|:-----|:-----|:-----|
| **SoC UART 调试串口** | 串口日志、UART 恢复模式（救砖 / 重刷系统） | 平台运维 |
| **ST-LINK / SWD 调试口** | 接口板 MCU 固件烧录 | 固件开发者 |
| **内部 MCU host-link** | 核心板与接口板 MCU 的内部通信（`/dev/ttyS0 @ 921600`），**不是对外接口，勿接外设** | 平台内部 |

前两类的操作步骤与接线照片见[系统烧录](../3-software-guide/2-system-flashing.md)：

| 目的 | 入口 |
|:-----|:-----|
| UART 恢复模式（救砖 / 重刷） | 拨码开关 BOOT0 OFF、BOOT1 ON + Reset 键（[§2.1](../3-software-guide/2-system-flashing.md#21-进入-uart-恢复模式)） |
| 接口板 MCU 固件烧录 | ST-LINK / SWD 连接（[§4](../3-software-guide/2-system-flashing.md#4-接口板-mcu-固件烧录)） |
| 串口日志 | UART 调试线（[§1.4 硬件连接](../3-software-guide/2-system-flashing.md#14-硬件连接)） |

> 注意区分：SoC 的 **BOOT0/BOOT1 拨码开关**用于整机引导模式切换；接口板 MCU 的 **PA14 引脚**也叫 BOOT0（与 SWDCLK 复用），那是 MCU 内部烧录的事，与整机拨码无关。
