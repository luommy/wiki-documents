## 系统全景

```
┌──────────────────────────────────────────────────────────┐
│                     NeoMind 主进程                         │
│                                                          │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌─────────┐ │
│  │ API 服务  │  │ MQTT     │  │ 规则引擎  │  │ Agent   │ │
│  │ (Axum)   │  │ Broker   │  │          │  │ (LLM)   │ │
│  │ :9375    │  │ :1883    │  │          │  │         │ │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘  └────┬────┘ │
│       │              │              │             │      │
│       └──────────────┴──────┬───────┴─────────────┘      │
│                             │                            │
│                    ┌────────▼────────┐                    │
│                    │  Telemetry      │                    │
│                    │  (redb)         │                    │
│                    │  data/*.redb    │                    │
│                    └─────────────────┘                    │
│                                                          │
├──────────────┬───────────────┬───────────────────────────┤
│              │               │                           │
│  ┌──────────▼──┐ ┌──────────▼┐ ┌───────────┐ ┌────────┐ │
│  │ 扩展进程 1   │ │ 扩展进程 2 │ │ 扩展进程 3 │ │  ...   │ │
│  │ (YOLO)      │ │ (Weather)  │ │ (OCR)      │ │        │ │
│  └─────────────┘ └────────────┘ └───────────┘ └────────┘ │
└──────────────────────────────────────────────────────────┘
      ▲                                      ▲
      │ Webhook / MQTT                       │ FFI
      │                                      │
  ┌───┴──────┐                        ┌──────┴───────┐
  │  IoT 设备  │                        │  ML 模型      │
  │  相机/传感器│                        │  (ONNX/PyTorch)│
  └──────────┘                        └──────────────┘
```

**四个核心子系统**：

1. **API 服务**（端口 9375）— Web UI 和 REST API 的入口，所有操作经此进出
2. **MQTT Broker**（端口 1883）— 设备通信枢纽，内置无需额外安装
3. **规则引擎**— 事件驱动的自动化，DSL 定义触发条件和动作
4. **Agent**（LLM）— 自然语言理解 + 工具调用，是"大脑"

所有子系统共享 **Telemetry** 存储（redb），数据文件落在 `data/` 目录。

## 数据生命周期

一条数据从设备到仪表板的完整路径：

```
设备                   NeoMind                      用户
                       主进程
┌──────────┐          ┌─────────────────────────────────────┐    ┌──────┐
│ 传感器    │──MQTT──▶│ MQTT Broker                         │    │      │
│          │          │   │                                 │    │ 仪表板│
│ 温度 25°C │          │   ▼                                 │───▶│      │
│          │          │ Telemetry 存储 (redb)               │    │ AI   │
│          │          │   │                                 │───▶│ Chat │
│          │          │   ├──▶ 仪表板 WebSocket 推送         │    │      │
│          │          │   ├──▶ 规则引擎检查 (是否超阈值?)     │    │      │
│          │          │   └──▶ Agent 数据源 (供 LLM 查询)    │    │      │
└──────────┘          └─────────────────────────────────────┘    └──────┘
```

**关键点**：
- 数据写入 **一次**（到 Telemetry），**多路消费**（仪表板 / 规则 / Agent）
- 仪表板通过 **WebSocket** 实时推送，无需轮询
- 规则引擎在数据写入后**立即评估**，满足条件即触发动作
- Agent 在执行时**按需拉取**最新数据

## 扩展模型

扩展是 NeoMind 的能力扩展机制——用 Rust 写的插件，运行在独立进程中。

```
┌────────────────────────────────┐
│        NeoMind 主进程           │
│                                │
│  ExtensionRunner                │
│    ├─ spawn 进程 ──────────────┼──▶ ┌─────────────────┐
│    │                           │    │  扩展进程         │
│    │ ←──── FFI (C ABI) ────────┼────│  impl Extension  │
│    │                           │    │  neomind_export! │
│    │  metric / command 转发     │    │                  │
│                                │    │  ┌─────────────┐ │
│                                │    │  │ ML 模型      │ │
│                                │    │  │ (lazy load)  │ │
│                                │    │  └─────────────┘ │
│                                │    └─────────────────┘
└────────────────────────────────┘
```

**设计原则**：
- **进程隔离** — 扩展崩溃不拖垮主服务
- **最小权限** — 启动时声明 capability，未声明即拒绝
- **延迟加载** — ML 模型首次调用才加载，加载后常驻
- **FFI 通信** — 跨进程数据用 serde JSON 序列化

> 写扩展的完整流程见 [扩展开发实战](../developer-guide/7-extension-development.md)。

## Agent 模型

Agent 是 NeoMind 的"大脑"——接收自然语言，理解意图，调用工具执行。

```
用户输入                    Agent 执行循环
┌──────────┐              ┌──────────────────────────────────┐
│ "温度     │              │                                  │
│  超过30   │───LLM───▶   │  1. 理解意图（LLM）                │
│  度时     │              │  2. 选择工具（LLM tool choice）    │
│  通知我"  │              │  3. 执行工具（CLI / 设备 / 扩展）  │
│          │              │  4. 观察结果                      │
│          │              │  5. 继续或回复（循环 2-4）          │
└──────────┘              └──────────────────────────────────┘
                                     │
                                     ▼
                           ┌──────────────────┐
                           │ 创建规则 + 通知渠道 │
                           │ 执行结果          │
                           └──────────────────┘
```

**两种触发方式**：
- **对话触发** — 用户在 AI Chat 中提问，Agent 实时响应
- **定时触发** — Agent 按 schedule 定期执行（如每 5 分钟巡检设备状态）

**工具系统**：Agent 通过 `neomind` CLI 命令操作一切（设备 / 规则 / 仪表板 / 扩展）。已安装扩展的 commands 自动暴露给 LLM。

## 为什么不用云端？

NeoMind 的核心理念是**边缘优先**：

| 维度 | 云端方案 | NeoMind（边缘） |
|------|---------|----------------|
| **延迟** | 100-500ms（网络往返） | `<10ms`（本地推理） |
| **隐私** | 数据离开设备 | 数据全程不出局域网 |
| **离线** | 断网即不可用 | 100% 离线可用（Ollama） |
| **成本** | 持续 API 计费 | 一次性硬件成本 |

当然，NeoMind 也支持接入云端 LLM（OpenAI / Anthropic / GLM），在需要更强能力时灵活切换。
